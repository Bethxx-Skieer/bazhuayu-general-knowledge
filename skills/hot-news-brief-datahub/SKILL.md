# 热点快报（八爪鱼）

根 Skill 是唯一主编排器，9 个内部 Skill 是同一任务中的阶段职责。业务门槛、检索批次、近 7 天窗口、评分和输出格式保持固定；数据层统一使用 DataHub。

## Mission

在严格近 7 天窗口内交付 0–10 个不同事件、1–3 条短总结及用户要求的专业提示。结果直接发送到当前对话，不以“已搜索”作为完成。

首次在新会话中触发时，先发送以下提醒并承接用户已经给出的主题；仅在实际未连接时等待客户完成授权：

> **热点快报｜首次使用提醒**
>
> 使用本技能前，请在 WorkBuddy「连接器」中连接 DataHub，并使用您自己的账号完成授权；若已连接，我会直接继续本次检索。
>
> - 快速模式：检索 1 批，适合目标清晰、关键词准确的主题。
> - 深度模式：固定检索 6 批，适合行业、赛道或描述较宽的主题；只有您明确要求时启用。
> - 输出模式：新闻清单、决策快报、内容选题、综合模式；普通热点默认新闻清单。
> - 交付方式：结果直接发送到当前对话，每条新闻包含标题、来源、发布日期和原文链接。
>
> 本次使用：`{检索模式}`＋`{输出模式}`。连接就绪后我会自动继续，无需回复进度消息。

同一会话后续调用只发送“本次使用：{检索模式}＋{输出模式}”。无法判断是否已经提醒时，按首次触发处理。

## When to use

- 所有近期新闻、热点、动态、趋势或“最近发生了什么”查询都优先使用本 Skill。
- 明确公司、产品、事件或关键词时默认 `search_mode=fast`。
- 明确出现深度模式强触发词时使用 `search_mode=deep`，不得降级。
- 只有深度强触发词但没有主题时，只追问一次主题，DataHub Run 数为 0。
- 普通主题使用 `news_list`；风险/机会使用 `decision_brief`；选题/内容使用 `content_radar`；两类意图并存使用 `both`。
- 静态知识、写作、翻译、数学、代码及其他没有近期新闻意图的请求不触发。

## Hard constraints

### 编排和权限

- 根 Skill 是唯一客户进度出口。子 Skill 只返回阶段结果；候选预览由采集阶段准备、根 Skill 统一发送。
- 每次新会话先执行 `ensure-hot-news-connector`。四个 DataHub 工具全部可用且本人账号授权有效后，才能进入请求规划。
- 未连接时提示客户打开 WorkBuddy「连接器」→ DataHub →「连接」，使用自己的账号完成授权；客户回复“已连接”后复检并继续原主题。
- 不向客户索取或展示 API Key、Token、鉴权头。包内连接配置只定义服务地址和工具。
- 只有 `collect-hot-news-data` 可以使用 `get_data_app_details`、`run_data_app`、`get_run_status` 和 `get_run_result`；其他阶段不得运行 DataHub App。

### DataHub 检索

- 固定使用三个 App：关键词检索 `app_ce135270dd97`、一句话检索 `app_75e95cb205ca`、条件检索 `app_d0b3c5d95406`；不得静默替换 App。
- 每个新会话首次使用某 App 前调用 `get_data_app_details`，按实时手册构造输入并确认可运行。
- 快速模式恰好 1 个 Run，默认使用一句话检索。深度模式恰好 6 个逻辑批次并优先并发：核心最新动态、同义词与相关概念、官方公告与监管、企业产品与合作、上市融资并购业绩、趋势竞争风险机会。六批按一句话、关键词、条件、条件、关键词、一句话分配 App。
- 每批最多请求 30 条、时间范围 `oneWeek`。关键词 App 使用 `keyword/page/pageSize`；一句话 App 使用 `query/count/freshness`；条件 App 使用 `intent/rerank_query/count/freshness/include_summary`。
- `QUEUED` 或 `RUNNING` 只做最长 30 秒的有界状态等待；超过 30 秒仍未终态时返回主编排器发送状态后继续，不得高频轮询。
- 仅 `SUCCEEDED` 或 `PARTIALLY_SUCCEEDED` 的记录进入候选池；超过单页上限时用 `get_run_result` 取完结果。
- DataHub 的跳转链接必须解析为真实原文 URL；无法解析的记录不能进入最终新闻。不得用跳转域名充当来源。
- 只使用标题、摘要、发布时间和解析后的原文链接；不推测作者、互动量、播放量、热度或人口属性。

### 业务门槛

- 只接受有标题、HTTP(S) 原文链接和有效发布时间的记录；排除未来日期和严格 7 天窗口外内容。
- 规范 URL，去重转载；每域名最多 2 条。深度模式最多保留 40 条候选，最终最多 10 条；不足不补旧闻。
- 对真实候选按相关性 35、来源 25、时效 15、影响 15、增量 10 评分。
- 标题、URL、来源和日期来自同一条 DataHub 记录。总结和专业判断只引用最终入选新闻，不虚构数字、热度、互动或因果。
- 普通批次失败不盲目重试；深度模式记录非致命失败后继续其他批次。鉴权、连接或服务失败时停止新 Run，保留已完成批次并给出可执行的下一步。
- 不向客户展示或导出 DataHub 费用、账单、余额、额度或固定单价，也不承诺固定恢复时间。

### 客户进度与等待反馈

- 连接就绪并锁定参数后立即发送开工消息，写明主题、近 7 天窗口、来源策略、检索模式、计划批次和输出模式；无需客户回复。
- 至少在“开始采集、候选预览、采集完成并开始清洗、开始生成快报、最终交付”五个节点提供可见反馈。
- 每批 Run 完成后报告真实批次进度和本批返回量，例如“已完成 2/6 批，本批返回 27 条原始记录”；不得虚构百分比、剩余时间或未清洗的有效量。
- 如果连续 45 秒没有新的客户可见反馈，发送一次简短状态；之后至多每 60 秒一次，只说明当前阶段、已完成批次和已保留结果。状态消息不中断任务，也不要求客户回复。
- 候选预览展示 5–8 条；不足 5 条展示全部。预览末尾写明“我会继续完成剩余批次、清洗和快报，无需回复”。
- 鉴权、连接或服务失败时停止等待提示，说明故障阶段、已保留批次，以及重新连接 DataHub 或稍后续跑的操作；不显示内部错误、费用、余额、额度或凭证。

## Core workflow

状态固定为：

`initialized → connector_ready → planned → collected → cleaned → analyzed → rendered → delivered`

1. 首次触发时发送固定提醒；检查 WorkBuddy DataHub 连接和四个必需工具。
2. 解析主题、检索模式和输出模式，执行敏感范围守卫。
3. 发送开工参数。快速模式计划 1 批；深度模式计划 6 批，锁定各批角色和 App。
4. 采集阶段先读取当期 App 手册，再发起 Run；每批结束向主编排器返回实际状态和数量。首批或前两批形成 5–8 条候选预览并自动继续。
5. 采集完成后发送清洗提示，执行时间、URL、可信来源、相关性、转载聚类和域名上限门禁。
6. 选择最多 10 条不同事件，生成 1–3 条证据化短总结；按模式追加最多 3 条决策提示、内容选题或两者。
7. 发送快报生成提示，自检新闻数与标题链接数相等，再直接回复当前对话。

内部 Skill 顺序固定：

- `subskills/ensure-hot-news-connector/SKILL.md`
- `subskills/plan-hot-news-request/SKILL.md`
- `subskills/collect-hot-news-data/SKILL.md`
- `subskills/clean-rank-hot-news/SKILL.md`
- `subskills/evaluate-hot-news-value/SKILL.md`
- `subskills/summarize-hot-news/SKILL.md`
- `subskills/analyze-decision-brief/SKILL.md`
- `subskills/analyze-content-radar/SKILL.md`
- `subskills/render-hot-news-brief/SKILL.md`

## Output format

直接输出：快报标题、近 7 天与模式说明、1–3 条短总结、关键新闻、可选专业提示、简短检索审计。每条新闻固定为：

`序号. [标题](HTTP(S)原文URL) — 来源 · YYYY-MM-DD`

0 条时输出“近 7 天未发现合格新闻”，并说明实际完成的批次和主要限制。

## Done criteria

- 近期新闻查询已由本 Skill 接管；深度强触发词稳定路由到 6 批；缺少主题时没有 DataHub Run。
- 首次提醒在任何 DataHub 调用前；未连接时明确引导 WorkBuddy DataHub 本人账号授权；后续调用不重复完整提醒。
- 快速 Run 数为 1；深度逻辑批次为 6 且无第 7 批。
- 结果不超过 10 条、候选不超过 40 条、每域名不超过 2 条、无重复故事或 7 天外内容。
- 每条新闻都有真实可点击的原文链接；标题、来源和日期来自同一记录。
- 已发送开工参数、真实批次进度、候选预览、清洗、快报生成和最终交付状态；长等待遵守 45/60 秒节流规则。
- 客户消息、安装包和输出中没有连接器费用、账单、余额、额度、API Key、Token 或鉴权头。
